## A 已采用这个方案
```flow LR
[同一份数据与prompt] -> [Peter或原生Codex执行]
[Peter或原生Codex执行] -> [代码、表格、图片、报告和轨迹]
[代码、表格、图片、报告和轨迹] -> [我逐项复核并记录证据]
```

```callout ok 图形无需固定标准样式
检查数据、坐标、标注和结论是否对应。
数值与统计方法仍需结合原始输入核对。
```

## B 本地与AWS保留哪些文件
| 内容 | 当前处理 |
|---|---|
| run.py、peter.R | 启动真实模型，完成三轮请求 |
| prompts.json | Peter与Codex读取同一份题目 |
| prepare/与source-hashes.json | 准备数据，核对关键哈希 |
| shared/ | 记录进程、计时、输入读取和轨迹 |
| 模型生成的分析代码与图片 | 保存到每次实验的workspace |
| 旧tasks参考答案、自动评分器 | 移出运行目录；仅在本地reference归档 |
| A2/C2/C3固定执行与自动回放 | 暂停；原始轨迹继续保留 |

本次重新核对：29个核心文件与15个兼容链接一致。
gptr包另外148个文件的哈希一致。
服务器aws目录没有tasks目录或评分器文件。

## C 怎么判断答案正确
| 检查对象 | 我会查看的证据 |
|---|---|
| 数值 | 原始数据、计算代码、关键结果独立重算 |
| 统计 | 患者配对、分母、置信区间和多重检验 |
| 图形 | 实际图片与绘图数据、轴和标签 |
| 科研解释 | 结论是否超出样本量和数据范围 |

status=ok只表示执行完成。
review_status=pending表示科学结果尚未复核。
复核意见单独保存，不覆盖原始运行记录。
