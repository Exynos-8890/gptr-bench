## A 只维护一个文件
```callout ok aws/prompts.json
T01–T10各有三条完整用户消息。
修改这个文件，就能同时修改A1与C1。
科学任务、输出要求和工具使用说明都在文件中。
```
```flow LR
[prompts.json] -> [A1：gptr读取原文]
[prompts.json] -> [C1：Codex读取原文]
[A1：gptr读取原文] -> [三轮用户消息]
[C1：Codex读取原文] -> [三轮用户消息]
```

## B 怎样兼容两种执行方式
| 场景 | 共用说明 |
|---|---|
| R会话已有raw | 直接使用raw |
| 独立脚本尚未载入数据 | 读取input.rds为raw |
| 从Shell执行R | 使用固定相对路径的测量启动器 |
| 输出文件 | 写入当前工作目录 |

两边不再追加各自的路径和任务说明。
用户允许保留必要的微小差异；目前无需额外用户消息。
gptr与Codex各自的系统指令、工具定义仍有区别。

## C 核对与使用
本地与AWS的45个核心文件哈希一致。
云端环境检查与6项离线测试通过。
临时SSH访问规则已撤销。

运行入口与命令保持不变。

离线测试核对gptr消息记录与Codex提交内容。
