## C 五组如何运行，如何记录大文件读取

| 组别 | 模型与R状态 | 参考执行方式 |
|---|---|---|
| A1 | 真实模型；gptr常驻R会话 | 自主完成三轮科研请求 |
| C1 | 相同真实模型；普通R脚本与文件 | 可缓存、合并步骤或恢复中间结果 |
| A2 | fake provider；实际gptr循环 | 回放标准步骤，或已经验证的A1轨迹 |
| C2 | 每轮请求新建R进程 | 共三个进程，每轮内部连续执行多个块 |
| C3 | 一个R进程 | 批量执行相同标准计算 |

```flow LR
用户请求1 -> 数据审计与主要设计
数据审计与主要设计 -> 用户请求2
用户请求2 -> 科学分析与统计诊断
科学分析与统计诊断 -> 用户请求3
用户请求3 -> 稳健性验证与解释
```

C2只恢复该轮实际需要的对象。
三个R进程不意味着原始大文件必定读取三次。
原始数据、状态对象和拟合结果的恢复会分开计时。

| 记录内容 | 导出证据 |
|---|---|
| 每次RDS读取或保存 | 开始与结束、文件、字节、进程、请求、耗时和成功状态 |
| 三轮请求与工具步骤 | 独立边界事件、R调用数和全部可见工具数 |
| 整体执行与内存 | 总时长、每20毫秒采样的进程树RSS、已知token |
| 每次试验时间线 | `timeline.csv`、`timeline-notes.json`、`timeline.png` |

RDS耗时包括序列化或反序列化，不能称为纯磁盘传输时间。
请求、工具和读取区间有重叠，不能直接相加。
CLI未公开的内部模型轮次、调用数和美元费用会保留为未知。
