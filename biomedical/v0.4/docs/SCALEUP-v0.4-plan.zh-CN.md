## A 对标结论：规模与科研复杂度都要校准

```callout info 本版按论文基准包校准，升级为完整科研任务
十任务都增加统计诊断、稳健性验证与有依据的解释。
参考回放规划18—24次R工具调用，真实运行先按15—30次量级预跑校准。
正式T01改为完整975275细胞；10万细胞版只作预跑。
```

论文的任务确实比v0.3“质控、汇总、改阈值”更复杂。
其公开单细胞示例还包含患者级整合、统计比较、纵向分析和生物学解释。
见[论文示例与过程评分](https://www.biorxiv.org/content/10.64898/2026.05.12.724604v2.full)。
本版据此增加完整的研究问题与验证链。

T03首次完整预跑在1800秒时超时，第二轮统计计算尚未结束。
后续T03完整预跑和正式收集统一采用每组14400秒上限。
保留全部576个样本、60660个基因、三轮请求和既定统计方法。
原超时与中断记录保留；新预跑全部通过后再冻结正式配置。

第二轮预跑发现筛选表列名要求不清，已中断并保留证据。
本版补齐列名要求，检查器接受逻辑列keep或retained。
检查器要求筛选表覆盖全部源基因；离线回归8项全部通过。

## C 完整科研流程：三轮请求不再只是改阈值

```flow LR
科研问题与数据审计 -> 主要分析与统计诊断
主要分析与统计诊断 -> 独立检查与稳健性分析
独立检查与稳健性分析 -> 证据汇总与生物学解释
```

**三轮请求对应一项完整研究，包含下面这些实质工作。**

|---|---|---|---|

## D 五组对照、模型设置与计划运行量

| 组别 | 如何完成任务 | 每任务计划次数 |
|---|---|---:|
| A1：真实gptr | 模型经gptr操作常驻R会话 | 3次独立真实试验 |
| C1：真实Codex | 同一模型自主组织R脚本与文件 | 3次独立真实试验 |
| A2：标准步骤回放 | fake回复驱动实际gptr循环 | 10次 |
| C2：分步RDS | 每个用户请求启动新R并恢复状态；组内执行相同参考块 | 10次 |
| C3：批量Rscript | 相同标准计算在一个R进程内完成 | 10次 |

A1与C1都可以自行组织代码，C1可以缓存、合并或减少数据读取。
C2按用户请求分成3个R进程，不按18—24个参考块反复重启。
两组真实执行使用相同数据、任务要求、方法、资源限制和输出规则。

**模型与设置。**

模型统一为 `gpt-6.1-sol`，推理强度显式设置为 `low`。
冻结同一Codex CLI版本，首选沿用0.165.0。
两条路径都记录最终启动参数和生效设置，不依赖全局默认值。
A1的参数透传在benchmark启动层补齐并验证。
[Codex配置参考](https://developers.openai.com/codex/config-reference/)列出了 `model_reasoning_effort` 设置。

**真实A1轨迹还要经过验证后回放。**

```flow LR
A1真实轨迹 -> 干净环境重跑
干净环境重跑 -> 产物与过程检查
产物与过程检查 -> A2轨迹回放: 通过后每条10次
```

| 十任务合计 | 计划数量 |
|---|---:|
| 独立真实试验：10任务×2组×3次 | 60 |
| 标准步骤：10任务×3组×10次 | 300 |
| 捕获回放：最多30条有效A1轨迹×10次 | 最多300 |
| 全部轨迹有效时的总量 | 660 |

60次才是独立的模型试验数量。
回放重复用于估计执行波动，不增加模型试验样本数。
不兼容轨迹如实记为缺失；错误与超时也保留。
正式统计包含实际成功数、失败数和消耗时间。
干净环境验证与预跑另行记录，不进入上述正式执行数量。

T01将运行升级后的完整科研任务；旧v0.3简单任务不与其混合统计。
首次预跑沿用每次1800秒和100万token上限。
如某任务需要调整预算，应在正式收集前统一冻结。

## E 测量方案：把每次读取放到图上

**继续测总时长，并让两组都具备独立的数据加载计时。**

v0.3中，A1-2单次读取约1.64 GB的RDS用了2.334秒。
C1-3四次读取被包含在外部命令中，没有独立读时。
这一缺口在十任务收集前补齐。
查证见[现有报告E节](../../v0.3/docs/REPORT-v0.3-full.zh-CN.html)。

```sequence num
participants: 用户请求, Agent, R执行, 加载记录
用户请求 -> Agent: 提交本轮分析
Agent -> R执行: 执行R代码
R执行 -> 加载记录: 数据加载开始，记录文件和进程
加载记录 --> R执行: 数据加载完成，记录耗时
R执行 --> Agent: 返回计算与产物
Agent --> 用户请求: 完成本轮回复
note R执行, 加载记录: 复用已有对象时，没有新的大文件加载事件
```

数据加载使用相同的benchmark计时入口。
A1预加载和C1脚本中的每次加载都写入同一事件格式。
C1仍可自由选择加载次数和脚本组织方式。
先用小任务核对记录是否覆盖实际读取，再开始正式实验。

| 要测的量 | 怎样记录与展示 |
|---|---|
| 整体耗时 | 从执行启动到最终回复和进程收尾；下载、准备和检查在计时外 |
| 每次大文件加载 | 独立开始与结束事件；文件、字节数、进程、所属请求 |
| 加载次数与累计加载时间 | 区分原始数据、状态文件和拟合对象恢复 |
| 每轮请求 | 记录进入、最终回复结束和两轮之间的切换 |
| R工具与计算 | 工具开始和结束；计算计时位于工具内部，不能重复相加 |
| 状态保存与恢复 | 记录序列化、反序列化和相应文件大小 |
| 内存 | 继续每20毫秒采样进程树RSS，报告采样范围 |
| 模型交互与用量 | 记录可观察的外层请求、token及已知成本；内部调用数未知则留空 |
| 正确性与失败 | 产物检查、过程检查、超时、错误和回放兼容性 |

每次加载指从文件恢复可使用的R对象，也包含反序列化。
不能将它直接解释为纯磁盘传输时间。
文件大小乘读取次数只能称为逻辑加载字节数。
系统真实读盘字节若无法获得，就记为未知。

每任务输出一个统一甘特图，展开全部三轮请求。
图中分别标出加载、工具执行、模型与程序交互，以及请求切换。
累计工具时间与模型交互时间有重叠时，不作直接加总。

## F 数据准备、独立检查与过程核对

```flow LR
公开发布文件 -> 选定真实样本并对齐
选定真实样本并对齐 -> 完全载入的R对象与RDS
完全载入的R对象与RDS -> 五组正式任务
五组正式任务 -> 独立产物与过程检查
```

下载、格式转换和预先声明的样本选取在正式计时前完成。
任务要求的QC、特征工程、拟合和图计算留在计时内。
每个任务冻结源文件哈希、版本、样本ID和选取规则。
同一任务的五组收到逐字节相同的RDS及任务说明。

首轮优先使用完全驻留内存的矩阵和表格。
准备阶段分别转换VCF、BED和H5文件。
只保存外部文件路径的RDS不算已加载完整数据。
较大任务先做容量预检；不适合本机的全量层明确标为未测。
较小层只选真实观测，不复制样本放大规模。

**每项任务都要有数据与过程检查，不能只核对一个终值。**

| 任务 | 科研过程与答案验收重点 |
|---|---|
| T01 | 患者而非细胞为统计单位；分母、配对人数、效应区间、FDR与时点顺序核对；不虚构临床响应标签 |
| T02 | 同一病例队列比较模型；删失和事件编码、模型诊断、患者级重采样与观察性解释核对 |
| T03 | 患者配对与样本设计、归一化、差异方向、FDR、通路背景集及稳健性核对 |
| T04 | 人群内HWE、缺失与MAF、LD规则、PCA子空间、Fst和子集稳定性核对 |
| T05 | 版本、等位基因、候选区域、功能背景与映射敏感性核对；距离合并不冒充LD独立或因果定位 |
| T06 | 坐标、重复关系、峰宽与背景匹配、富集和敏感性核对；重叠与机制结论分开 |
| T07 | 突变坐标、划分与泄漏检查、模型比较、深度分层、候选约束和预测不确定性核对 |
| T08 | 尺度、参考通道、重复和批次、差异及FDR、功能背景与缺失敏感性核对 |
| T09 | 划分、训练折内预处理、嵌套调参、测试集使用、判别校准、置换与特征稳定性核对 |
| T10 | spot与图、孤立点、随机化方案、空间统计和FDR、空间域对齐与邻域敏感性核对 |

参考计算层的整数、ID、过滤集合和边界要求一致。
浮点量原则上采用绝对及相对容差 `1e-6`，特殊量另行冻结。
真实组采用等价方法时，按相应有效路径核对方法与计算一致性。
不能因方法不同而强求所有系数或P值与单一参考完全一样。

每任务设置约8—10个关键过程标准，记录充分、部分或缺失。
覆盖数据处理、方法选择、统计有效性、验证、生物解释和来源依据。
数值正确但用了错误统计单位或泄漏测试集，不能作为成功科研任务。
首轮仍用规则与人工核对，不新增LLM裁判。

**完整规模的资源要求。**

T01现有10万细胞版本只用于调试与测量覆盖检查。
正式完整队列建议使用至少64 GiB RAM的机器，并通过可用内存预检。
先前对完整准备和执行的预算约40 GB，当前32 GiB机器不满足该层。
若大机器未就绪，标记完整层未测，不以小子集声称已对齐论文规模。
