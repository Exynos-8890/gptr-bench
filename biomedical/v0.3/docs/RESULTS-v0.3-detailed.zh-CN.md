## A 摘要与研究背景

```callout info 五组做同一个分析任务，比较不同的执行方式
本轮66次正式执行均通过独立检查。
真实组中，gptr耗时中位数较低。
固定步骤中，单进程Rscript最快。
```

生物医学分析经常是连续对话：先检查数据，再分析，最后修改条件。
同一份表达矩阵、质控结果和分组信息会在请求之间复用。
gptr把这些对象保留在R会话中，供后续请求继续使用。
普通coding agent也可以保存文件或调整脚本组织。

因此，实验同时考察完整agent工作流和固定代码的执行成本。
前者允许模型自行选择代码；后者统一R计算步骤。

| 研究问题 | 对应比较 | 主要观察 |
|---|---|---|
| 用户连续提问，哪条完整工作流更快？ | A1与C1 | 真实模型参与的端到端耗时 |
| 同一段R计算，执行方式有何差异？ | A2、C2与C3 | 常驻会话、状态读写和批量执行的表现 |
| 真实生成的分析过程能否重现？ | A1轨迹进入A2 | 先验证计算，再进行fake回放 |

阅读顺序为：共同任务 → 五组总图 → 各组时序 → 验证 → 结果。
底部的查证表提供配置、代码和原始记录入口。

## B 共同输入与三轮任务

**数据从哪里来？**

使用公开研究队列[GSE236581](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE236581)。
按固定规则选取原始细胞，保留全部基因和原始计数。

```flow LR
GSE236581原始队列 -> 固定选取10万细胞
固定选取10万细胞 -> 保留全部36027个基因
保留全部36027个基因 -> 同一份稀疏RDS输入
```

```kv cols=2
正式输入: 100000个真实细胞
基因数: 36027
输入RDS: 1.64 GB
覆盖范围: 22位患者、169份样本
分析分组: 168个患者／组织／时点组合
原队列规模: 975275个细胞
```

分组会合并患者、组织和时点相同的样本。
本轮测量10万细胞这一层。
全量队列因本机内存预检未通过而未运行。
重新准备源文件后，输入RDS逐字节一致。

**用户究竟要求agent做什么？**

```flow LR
请求1细胞质控 -> 请求2首次表达汇总
请求2首次表达汇总 -> 请求3提高阈值重算
```

| 请求 | 计算内容 | 主要输出 |
|---|---|---|
| 1：检查数据 | 核对标识；从矩阵计算每个细胞的总计数与检测基因数 | qc.csv、cell-qc.csv |
| 2：首次分析 | UMI至少1000、检测基因至少500；按患者／组织／时点汇总 | baseline.csv |
| 3：修改条件 | 阈值提高到2000和1000；复用输入与质控结果重算 | revised.csv |

UMI总数是一个细胞的表达计数总和。
检测基因数是该细胞中计数大于零的基因数量。
两次汇总都计算全部基因，随后提取八个标记基因。
首次筛选保留99125个细胞，修订后保留69684个。

查证：[任务定义](../../tasks/single-cell.R) · [数据清单](../results/dataset.json) · [输入审计](../results/preparation-audit.json)。

## C 五组关系：两层对照，共用一个任务

```flow LR
共同输入与三轮任务 -> 真实模型自主生成代码
共同输入与三轮任务 -> 预先固定相同R步骤
真实模型自主生成代码 -> A1常驻R工作流
真实模型自主生成代码 -> C1脚本文件工作流
预先固定相同R步骤 -> A2实际gptr循环
预先固定相同R步骤 -> C2每步启动新R
预先固定相同R步骤 -> C3单个R批量执行
group 真实层: A1常驻R工作流, C1脚本文件工作流
group 固定步骤层: A2实际gptr循环, C2每步启动新R, C3单个R批量执行
```

A1与C1统一使用GPT 6.1 SOL和Codex CLI 0.165.0。
本轮A1也是通过Codex CLI调用模型，并接入gptr常驻R桥接。

| 组别 | 代码从哪里来 | 状态如何保留 | 这组的作用 |
|---|---|---|---|
| A1：真实gptr | 真实模型自主编写 | gptr中的常驻R对象 | 测量完整gptr工作流 |
| C1：真实Codex | 同一真实模型自主编写 | agent自行组织脚本与文件 | 测量普通coding agent工作流 |
| A2：gptr回放 | 固定回复提供确定的R操作 | 常驻R对象 | 保留真实gptr循环并重复执行 |
| C2：RDS回放 | 预先声明的相同R步骤 | 每步重新读取输入及所需RDS状态 | 测量分步重启与文件状态传递 |
| C3：单进程Rscript | 同一组固定R步骤 | 一个R进程内连续保留对象 | 提供批量执行基线 |

C1由agent决定脚本组织方式。
C2的协议明确规定每步启动新R进程。
C3用于观察合并执行可以达到的表现。

## D 真实层：模型如何完成三次连续请求

**A1：模型通过gptr使用同一个R会话。**

```sequence num
participants: 用户, GPT6.1SOL, gptr常驻R
用户 -> GPT6.1SOL: 请求1：质控
GPT6.1SOL -> gptr常驻R: 检查对象并计算质控
 gptr常驻R --> GPT6.1SOL: 返回结果，保留输入与QC
用户 -> GPT6.1SOL: 请求2：首次汇总
GPT6.1SOL -> gptr常驻R: 使用已有输入与QC
 gptr常驻R --> GPT6.1SOL: 写出baseline.csv
用户 -> GPT6.1SOL: 请求3：提高阈值
GPT6.1SOL -> gptr常驻R: 使用已有对象重新汇总
 gptr常驻R --> GPT6.1SOL: 写出revised.csv
```

**C1：模型生成脚本，借助文件传递分析状态。**

```sequence num
participants: 用户, Codex模型, Rscript角色, 文件状态
用户 -> Codex模型: 请求1：质控
Codex模型 -> Rscript角色: 本轮启动R进程1
文件状态 --> Rscript角色: 读取输入RDS
Rscript角色 -> 文件状态: 保存QC与分组
用户 -> Codex模型: 请求2：首次汇总
Codex模型 -> Rscript角色: 本轮启动R进程2
文件状态 --> Rscript角色: 输入RDS与QC状态
Rscript角色 -> 文件状态: 写出baseline.csv
用户 -> Codex模型: 请求3：提高阈值
Codex模型 -> Rscript角色: 本轮启动R进程3
文件状态 --> Rscript角色: 输入RDS与QC状态
Rscript角色 -> 文件状态: 写出revised.csv
```

图按任务阶段展开，省略了文本回复和检查性调用。
三个用户请求会延续同一个agent会话。
每次独立试验则使用新的会话和工作目录。

本轮每条A1真实轨迹都有四次R调用。
C1本轮实际采用分阶段脚本；协议允许其他脚本组织方式。
两组模型生成的代码可以不同，最终产物必须满足同一要求。

查证：[真实过程审计](../results/process-audit.json) · [三条A1轨迹索引](../results/trace-index.json)。

## E 固定步骤层：同一段R计算如何执行

**A2：fake回复驱动实际gptr循环。**

```flow LR
A2加载输入 -> gptr工具循环
固定回复脚本 -> gptr工具循环
gptr工具循环 -> A2质控
A2质控 -> A2首次汇总
A2首次汇总 -> A2修订汇总
group 同一个R进程保留状态: A2加载输入, gptr工具循环, A2质控, A2首次汇总, A2修订汇总
```

每个阶段都经过实际gptr执行循环。
权限检查和正常harness工作计入耗时。
fake provider提供预先确定的回复，不发送真实模型请求。

**C2：每步启动新R，原始输入重复加载。**

```flow LR
输入RDS -> R进程1做质控
R进程1做质控 -> [(QC与分组RDS)]
输入RDS -> R进程2首次汇总
QC与分组RDS -> R进程2首次汇总
输入RDS -> R进程3修订汇总
QC与分组RDS -> R进程3修订汇总
R进程2首次汇总 --> R进程3修订汇总: 依次执行
```

QC和分组信息从第一步保留到后续步骤。
每个新进程读取所需对象，完成当前计算后退出。
图中的分支表示数据依赖；实际运行依次完成三步。

**C3：一次启动，一次加载，连续完成全部计算。**

```flow LR
C3加载输入 -> C3质控
C3质控 -> C3首次汇总
C3首次汇总 -> C3修订汇总
group 同一个R进程内直接执行: C3加载输入, C3质控, C3首次汇总, C3修订汇总
```

C3直接执行固定代码，不经过gptr工具循环。
A2、C2、C3的这一层使用同一组R计算步骤。

查证：[R执行器](../../runner.R) · [编排与C2状态选择](../../run.py)。

## F 真实轨迹回放、正确性与计时

**A2还有第二种输入：来自真实A1的R操作。**

```flow LR
A1真实执行 -> 捕获R代码与调用顺序
捕获R代码与调用顺序 -> 干净环境重跑
干净环境重跑 -> {产物检查通过?}
产物检查通过? -> fake回复脚本: 通过
产物检查通过? -> 保留拒绝记录: 失败
fake回复脚本 -> A2原样执行R操作
A2原样执行R操作 -> 再次核对产物
```

固定步骤回放使用预先编写的标准计算。
真实轨迹回放还包含模型实际选择的检查和操作。
它们都使用A2机制，但在汇总中分别标记来源。
本轮重现可观察的R操作，模型内部请求边界未被完整复原。

**66次正式执行如何组成？**

| 部分 | 重复方式 | 次数 | 重复说明 |
|---|---|---:|---|
| 真实模型 | A1、C1各3次 | 6 | 独立的模型试验 |
| 固定步骤 | A2、C2、C3各10次 | 30 | 相同计算的执行波动 |
| 真实轨迹 | 3条A1轨迹各回放10次 | 30 | 同一轨迹的执行波动 |

后两类重复不能当作独立的模型试验。
1万细胞预检、兼容验证和额外复现单独存档。

**正确性是结果有效的前提。**

独立检查器核对细胞QC、组别、计数、总UMI和CPM。
整数计数要求完全一致；CPM容差为 `1e-6`。
参考计算用细胞总量和标记行求和，独立核对聚合结果。
六次真实执行也都核对了完整基因矩阵的聚合操作。

**计时从启动执行开始，到所需CSV写出结束。**

```flow LR
数据下载和准备 -> 工作区准备
工作区准备 -> (计时开始)
计时开始 -> 启动与数据加载
启动与数据加载 -> 按组执行三阶段任务
按组执行三阶段任务 -> 所需CSV写出
所需CSV写出 -> (计时结束)
计时结束 -> 独立检查器
```

真实组包含模型交互，所有组包含本组正常执行开销。
C2的重复启动与加载也包含在内。
图只表示计时边界，内部过程可以交错。
内存是进程树RSS的采样峰值。
系统缓存未强制清空，本轮不作冷缓存比较。

查证：[独立检查器](../../evaluate.R) · [测量明细](../results/summary.csv)。

## G 结果与讨论：三个问题分别得到什么答案

**完整真实工作流：两组都正确，gptr耗时中位数较低。**

```chart bar horizontal unit=s
A1真实gptr | 61.851
C1真实Codex | 72.692
```

A1耗时范围为58.65—61.93秒。
C1耗时范围为70.19—94.57秒。
两组各完成三次独立试验，耗时中位数相差约14.9%。

**固定计算：C3最快，C2其次，A2耗时最长。**

```chart bar horizontal unit=s
A2标准步骤 | 11.991
C2分步RDS | 10.358
C3单进程 | 5.116
```

这组结果说明，在本轮输入规模下，直接批量执行更快。
真实组与固定步骤组回答不同的问题，结果应分别阅读。

**真实轨迹：三条均可验证后回放。**

```chart bar horizontal unit=s
A1轨迹1进入A2 | 13.334
A1轨迹2进入A2 | 13.081
A1轨迹3进入A2 | 12.528
```

三条轨迹各完成十次回放，产物均正确。

**内存同样需要报告。**

| 组别 | 采样RSS峰值的组内中位数（MiB） |
|---|---:|
| A1真实gptr | 3731.9 |
| C1真实Codex | 2969.2 |
| A2标准步骤 | 3113.2 |
| C2分步RDS | 2768.4 |
| C3单进程 | 2868.9 |

RSS采样值包含进程树，不能当作精确的独占内存。
本轮A1的采样内存高于C1。
当前证据覆盖一个任务、一台机器和一个模型版本。
真实组差异覆盖完整工作流，尚不能推广到其他任务。

查证：[完整结果报告](../results/report.md) · [统计值](../results/metrics.json)。

**更细的任务定义。**

输出包含每组细胞数、总UMI、标记计数及CPM。
CPM等于标记计数乘一百万，再除以该组总UMI。
空组保留，计数与CPM均为零。
八个标记为 `CD3D`、`CD3E`、`CD8A`、`MS4A1`、`LYZ`、`NKG7`、`EPCAM`、`COL1A1`。

**离线复现一条已核对的轨迹。**

从仓库根目录运行，使用本地已准备的真实输入。
该命令先在干净环境验证计算，再执行一次fake回放。

```bash title="已验证的离线复现命令"
python3 dev/bench/biomedical/run.py --task single-cell \
  --input dev/bench/biomedical/data/gse236581-100000/input.rds \
  --arms A2 \
  --replay dev/bench/biomedical/reports/gse236581-v0.3/trace-a1-1.jsonl
```
